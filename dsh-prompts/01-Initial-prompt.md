Ты — Senior Python Developer и DevOps-инженер. Твоя задача — спроектировать и написать production-ready решение для двусторонней ретрансляции сообщений (текст + изображения) между веб-клиентом российского мессенджера MAX (`https://max.ru`) и Telegram.

### 1. Контекст и инфраструктура
- **Целевая платформа:** Одноплатный компьютер Orange Pi 5 Plus (процессор Rockchip RK3588, архитектура `linux/arm64`, 32 GB RAM, ОС Linux без графического окружения / headless).
- **Среда запуска:** Docker / Docker Compose.
- **Сетевая специфика:** 
  - Сервер находится в РФ (домашний резидентский IP). Трафик к `web.max.ru` должен идти напрямую без прокси, чтобы не триггерить антифрод MAX.
  - Telegram API на сервере заблокирован, но уже развернут собственный HTTPS-прокси на базе Nginx (например, `https://example.com`). Весь трафик бота Telegram должен идти исключительно через этот URL.
- **Конфиденциальные данные:** Учетные данные (номер телефона, токен Telegram-бота, ID целевого чата в Telegram, URL прокси, название нужного чата в MAX) должны передаваться строго через переменные окружения (`.env`).

### 2. Технологический стек
- **Язык:** Python 3.11+ (строго асинхронный подход `asyncio`).
- **Браузерная автоматизация:** `playwright` (Python) + Chromium (с использованием `launch_persistent_context` для сохранения сессии, cookies и IndexedDB в примонтированную директорию `./chrome_profile`).
- **Telegram Bot:** `aiogram` v3.x с переопределением базового сервера API через `TelegramAPIServer.from_base()` для работы через кастомный Nginx-прокси.

### 3. Функциональные требования
1. **Авторизация без GUI (Критически важный этап!):**
   - Так как на Orange Pi нет монитора и X-сервера, предусмотри интерактивный CLI-режим первичной авторизации (например, через запуск с флагом `--auth` или отдельный скрипт `auth.py`).
   - В этом режиме скрипт запускает Playwright (в headless-режиме), открывает `https://max.ru`, запрашивает в консоли терминала номер телефона, вводит его на странице, ждет ввода кода из СМС в терминале, завершает вход, открывает нужный групповой чат и сохраняет профиль браузера на диск.
   - Дополнительно опиши в README альтернативный способ первичной авторизации через временный VNC/noVNC внутри контейнера или через X11-forwarding (`ssh -X`), на случай если на странице входа появится графическая капча или QR-код.
2. **Ретрансляция MAX → Telegram (Чтение ДЗ):**
   - После запуска в основном режиме скрипт открывает целевой чат в `web.max.ru` и отслеживает появление новых входящих сообщений в реальном времени (через `MutationObserver` внутри `page.evaluate()` или периодический опрос DOM с дедупликацией по ID/хэшу сообщения).
   - Поддержка текста: извлечение имени отправителя и текста сообщения, отправка в Telegram-чат.
   - Поддержка изображений: в веб-версии MAX картинки могут отдаваться как `blob:` URL или требовать авторизационных кук. Реализуй скачивание изображений **внутри контекста браузера** (через `fetch()` + конвертацию в `base64` в `page.evaluate()`), декодирование в Python (`io.BytesIO`) и отправку в Telegram через `bot.send_photo()` с подписью (автор + текст).
   - Поддержка альбомов (если прислали несколько фото подряд) — желательно, но допустима последовательная отправка.
3. **Ретрансляция Telegram → MAX (Ответы в школьный чат):**
   - Если пользователь в Telegram делает `Reply` (ответ) на пересланное сообщение из MAX (или пишет в чат с определенным префиксом/режимом), бот перехватывает текст и/или прикрепленное фото.
   - Скрипт скачивает фото (если есть) с Telegram через настроенный Nginx-прокси во временную директорию, загружает его в чат MAX через `input[type="file"]`, вводит текст ответа и нажимает Enter.
4. **Антифрод и стабильность 24/7:**
   - Маскировка автоматизации: запуск Chromium с аргументами `--disable-blink-features=AutomationControlled`, актуальный десктопный `User-Agent`, удаление `navigator.webdriver`.
   - Имитация человеческого поведения: случайные задержки (`asyncio.sleep(random.uniform(1.0, 3.0))`) перед отправкой ответов, посимвольный ввод текста с небольшой задержкой.
   - Защита от утечек памяти Chromium: фоновая задача, которая раз в сутки (например, в 03:00 ночи) делает мягкую перезагрузку страницы (`await page.reload()`).
   - В `docker-compose.yml` обязательно учесть специфику ARM64 (образ `://microsoft.com` нужной версии) и выделить `shm_size: '2gb'` для стабильной работы Chromium.
