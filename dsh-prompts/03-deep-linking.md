Ты — Senior Python Developer. Мы продолжаем развитие нашего мультиаккаунтного моста `max-tg-bridge` (версия 2.0 на Python 3.11+, `asyncio`, `aiogram` v3.x, `playwright`, SQLite).

Твоя задача — спроектировать и реализовать **версию 2.1: Инвайт-ссылки (Deep Linking) для саморегистрации Слушателей и Владельцев**, чтобы администратору не приходилось вручную узнавать у людей их числовой `tg_user_id`.

### 1. Бизнес-логика инвайтов
1. **Генерация ссылок из админ-панели:**
   - В меню управления конкретным аккаунтом MAX (`/admin` → Выбрать аккаунт) добавь кнопку **«🔗 Создать инвайт-ссылку»**.
   - При нажатии админ выбирает тип ссылки:
     - **Для Слушателя (Read-Only):** может быть одноразовой (на 1 активацию) или многоразовой (с лимитом, например, на 5 человек / безлимитной, либо со сроком действия 24 часа).
     - **Для Владельца (Owner, Read-Write):** строго одноразовая ссылка для привязки основного пользователя этого аккаунта MAX.
   - Бот генерирует криптостойкий токен (`secrets.token_urlsafe(16)`) и выдает готовую deep-link ссылку формата `https://t.me<BOT_USERNAME>?start=inv_<token>`, которую админ может сразу переслать нужному человеку в Telegram.
   - Учти важный нюанс: так как бот работает через кастомный Nginx-прокси (`TG_API_BASE`), получи `username` бота при старте приложения через `await bot.get_me()` и сохрани в контексте/конфиге для формирования ссылок.

2. **Процесс активации пользователем (`/start inv_<token>`):**
   - Пользователь переходит по ссылке и нажимает «Запустить» (`/start`).
   - Бот проверяет токен в БД: существует ли он, не истек ли срок действия и не исчерпан ли лимит использований.
   - Если токен невалиден — отвечает: *«Ссылка недействительна или срок её действия истёк. Запросите новую у администратора»*.
   - Если токен валиден:
     - Бот автоматически берет из объекта `message.from_user` его `id` (`tg_user_id`), `full_name` и `@username`.
     - Если ссылка была для **Слушателя** — добавляет пользователя в таблицу `listeners` для привязанного `account_id`, записывая `full_name` и `@username` в поле `alias` (чтобы админ сразу видел в списке, кто именно подключился, без ручного ввода заметок).
     - Если ссылка была для **Владельца** — обновляет `owner_tg_id` у данного аккаунта MAX.
     - Уменьшает счетчик оставшихся использований токена (или помечает одноразовый токен как `used = 1`).
     - Отправляет пользователю приветственное сообщение с описанием его прав (например: *«Вы подключены к каналу «Школа 5Б» в режиме чтения. Сюда будут приходить сообщения и фото из чата MAX»*).
     - **Уведомление админу:** отправляет Супер-администратору (`ADMIN_TG_ID`) пуш-уведомление: *«✅ Пользователь Иван Иванов (@ivanov, ID: 123456789) подключился по инвайт-ссылке как Слушатель к аккаунту «Школа 5Б»»*.

3. **Управление активными инвайтами в админке:**
   - В меню аккаунта добавь раздел **«🎟 Активные инвайты»**, где админ видит список неиспользованных/действующих ссылок для этого аккаунта (роль, остаток активаций, срок жизни) и может **отозвать (удалить)** любую ссылку до её использования.
   - В списке подключенных слушателей теперь должно отображаться человекочитаемое имя и `@username` (например: `👤 Анна Смирнова (@anna_s) [12345678] — 🗑 Удалить`).
   - При удалении слушателя админом бот (опционально) отправляет удаленному пользователю уведомление об отключении от рассылки.

### 2. Изменения в базе данных (SQLite)
Добавь миграцию / обновление схемы в `store.py`:
- Таблица `invites`:
  - `id` (INTEGER PK)
  - `token` (TEXT UNIQUE, индекс)
  - `account_id` (INTEGER FK → `accounts.id` ON DELETE CASCADE)
  - `role` (TEXT: `'listener'` или `'owner'`)
  - `max_uses` (INTEGER, по умолчанию `1`)
  - `used_count` (INTEGER, по умолчанию `0`)
  - `expires_at` (DATETIME / TIMESTAMP, nullable)
  - `created_at` (DATETIME)
- Обнови таблицу `listeners`: добавь поля `username` (TEXT, nullable) и `full_name` (TEXT, nullable), чтобы сохранить совместимость с ручным добавлением по ID из v2.0.

### 3. Требования к реализации
- Используй стандартный фильтр `CommandStart(deep_link=True)` из `aiogram.filters`.
- Обеспечь защиту от race condition при одновременном переходе двух человек по одноразовой ссылке (используй транзакцию в SQLite при проверке и инкременте `used_count`).
- Выдай SQL-миграцию для обновления существующей БД `bridge.db` без потери данных v2.0, обновленный `store.py`, новые хендлеры для `admin_handlers.py` и обработчик `/start` для пользователей.
